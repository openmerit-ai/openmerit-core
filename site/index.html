A few useful details

Fair questions.

Is OpenMerit an agent?+

The terminal is a passive view of existing application evidence. For evaluations and model changes, OpenMerit works with your coding harness, such as Pi. The harness understands the project, builds evaluations, tests models, and performs authorized changes. OpenMerit coordinates the workflow and validates structured results and comparisons; it relies on the harness to perform the work and report honest evidence.

Which harnesses does it work with?+

The standalone terminal runs without a coding harness. Pi 0.87 is the implemented adapter for the separate comparison workflow. Other coding agents need an adapter to use the coordinator and protocol; installing the package does not add that integration automatically.

Building a harness adapter ↗
Do I need evaluations before I start?+

The terminal needs no evaluation suite. For model comparisons, setup in an interactive Pi session asks Pi to understand your task, confirm your requirements and permissions, and establish the necessary evaluations and measurements. Those checks need to reflect your actual product. Ordinary coding activity alone doesn’t measure product quality.

Setting up your first task ↗
Does it always choose the cheapest model?+

No. Comparisons use the quality, cost, speed, and other requirements you confirm. Several models may offer useful tradeoffs. OpenMerit checks the harness’s comparison of tested candidates against those requirements; it doesn’t promise one model that is best for every task, or guaranteed savings.

How much evidence does a recommendation need?+

That depends on your task and the sample requirements you confirm during setup. Reliability and consistency need repeated, representative runs. Missing or insufficient required measurements leave a candidate unresolved in the comparison. OpenMerit checks the reported measurements and comparison rules, but doesn’t independently prove that an external evidence source is truthful.

Understanding the evidence ↗
Will it change my model without asking?+

A proposal waits for /openmerit approve unless your policy enables automatic swaps and its required number of verified swaps has been reached. That number can be zero, so check the policy you confirm during setup. After a change, the workflow requires the harness to evaluate the new model and report the result. Model changes are carried out by the harness.

What if a new model performs worse?+

If post-swap evaluation reports a regression and your policy enables rollback, OpenMerit asks the harness to restore the previous model configuration. Otherwise it waits for your decision. Detection depends on the measurements and checks your harness provides; rollback depends on the harness being able to restore that configuration.

Does it keep running when Pi is closed?+

The terminal collects only while its CLI is running. For Pi comparisons, an explicitly authorized persistent policy can install a per-project macOS LaunchAgent. It checks for due work every five minutes while the user is logged in and requires working headless Pi authentication. Other platforms need an external scheduler. Unattended candidate discovery and model changes still need representative product validation.

How scheduled checks work ↗
Can I pause automatic checks?+

The /openmerit pause command persists across Pi restarts, blocks automatic due decisions and lifecycle follow-ups, and unloads the managed macOS LaunchAgent. It still records incoming signals and does not cancel already-active work or disable explicit commands. Resume restores scheduling only when the policy authorizes it. The standalone terminal is independent; stop its CLI to stop collection.

Current limitations ↗
Where does my data live?+

The terminal reads supported application code, configuration, request logs, exports, and authorized loopback runtime endpoints. It retains selected metadata in memory, without prompts, responses, or credentials, and clears its caches on exit. The Pi workflow separately stores project state, audit events, and evidence references in .openmerit/ and records entries in Pi history. Its configured providers and tools may receive project or evaluation data.

Read the security notes ↗
What does it cost to run?+

OpenMerit has no subscription fee. The terminal makes no inference calls, though collection uses local resources. Provider usage charges apply to Pi setup, candidate work, and verification; paid tools or infrastructure may add costs.

Is the evaluation budget a hard spending limit?+

OpenMerit tracks reported challenger spend, supplies the remaining allowance, rejects challenger results over the approved limit, and blocks another challenger intent when the allowance is exhausted. It does not independently meter provider billing or stop an in-flight request. Setup, baseline work, and swap verification have separate costs. Use provider spending controls as well as the evaluation policy.

Is OpenMerit ready for production?+

The terminal provides visibility into supported existing evidence; missing or incomplete sources remain visible. Pi model comparisons are intended for supervised product trials. Tests cover the implementation but do not establish better model choices or reliability for your workload. Inspect the evaluations and validate a supervised swap and rollback before relying on automation.
