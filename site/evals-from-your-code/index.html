A tool that writes evals from your codebase and tests cheaper models against them

OpenMerit reads the code around each LLM call, writes an eval for it and runs that same eval on your current model and on cheaper candidates. If your repository already has evals, they run alongside the generated one.

What the eval contains

For each task, OpenMerit’s harness reviews the code and writes a spec:

  • What the call receives, its steps and the tools each step uses.
  • What it outputs.
  • Criteria: what a right answer does.
  • Guardrails: what it must never do.

From that spec it writes typical, edge-case and guardrail cases, each with an expected answer.

How answers are graded

  • Labels and JSON are graded against the expected answer.
  • Free text, and every answer’s guardrails, are graded by one fixed judge model.

You stay in charge of the eval

  • Approval: you see the eval before anything runs: case counts, criteria, guardrails and judge.
  • Grading: before the search, you grade a sample of answers from your current model and a cheaper one. Where you and the eval disagree, the eval is wrong, and OpenMerit rewrites it from your grades. Only the cases you disputed change, and only the eval you accept is used to search. Before a model is recommended, you check a few of its answers.
  • Saving: once you accept it, the eval is saved in your repository under .openmerit/evals/<task>/. Later runs reuse it, and you can edit or delete it like any other file.

Limits

  • The scanner finds literal model IDs and common patterns. A model chosen far from where it’s used may need a manual correction.
  • Model calls in tests, fixtures and docs don’t become tasks.
  • A task needs at least five eval items.

Try it

Running OpenMerit on your machine is free: npm install -g openmerit, then openmerit setup in your repository. For OpenMerit Cloud pricing, contact us.
