OpenMerit vs LLM routers and gateways

A router or gateway decides at run time: each request goes through it, and it picks or forwards a model for that request. OpenMerit decides ahead of time. It writes an eval for each model call in your code, tests cheaper models against that eval and proposes changing the model name in your code. Your app keeps calling its provider directly, as it does today.

How they differ

QuestionRouter or gatewayOpenMerit
Where it runsIn the live request path, on every callOutside it. It runs when you start Scout, not when users call your app
What it decidesA model, and sometimes a provider or reasoning effort, for each requestOne model per task in your code, checked against an eval for that task
Evidence for the choiceThe request’s content, benchmarks, prices and usage signalsYour task’s own eval: cases written from your code, plus your repository’s evals when it has them
If it goes downRequests that pass through it are affectedNothing changes. Your app already calls the chosen model directly
What changes in your appThe endpoint or model name your app sends requests toThe model name for one call, after you approve it

Named examples

  • OpenRouter Auto Router (openrouter/auto): you send it as the model, and it picks a model and reasoning effort for each request through OpenRouter. OpenRouter charges no surcharge for the router.
  • Not Diamond: a router that returns a model recommendation for each request. Not Diamond Code runs as a local proxy next to the coding agent and sends derived metadata, not the payload, to its service.
  • Gateways such as LiteLLM, Portkey and Cloudflare AI Gateway: a single endpoint for access, keys, budgets and failover. You can host some of them yourself.

When a router is the better fit

  • Your traffic is open-ended, such as a chat product where you can’t predict what users will ask. A per-request router can adapt to each prompt.
  • You want failover between providers at run time.

OpenMerit fits best when your code makes the same kinds of calls over and over, such as classifying a ticket or drafting a reply. A fixed model checked against an eval is enough for those. The two can work together: OpenMerit can pick the model a gateway serves.

Two ways to run OpenMerit

  • On your machine: npm install -g openmerit. A CLI and MCP server for Claude Code and Codex. You use your own keys, there’s no OpenMerit account, and your code goes only to the model provider you choose.
  • Hosted: connect your coding agent to openmerit.ai/mcp, and OpenMerit runs the code review and the evals for you.

FAQ

Is OpenMerit a router?
No. It never handles your app’s requests.
Does it replace my gateway?
No. Keep your gateway for access, keys and failover. OpenMerit chooses which model your gateway calls.
How does it know a cheaper model is good enough?
A candidate qualifies only if it passes at least as many eval runs as your current model and loses no case your current model always passes. A switch also has to cost at least 10% less per call; a smaller saving is within what the measurement can tell apart.
