We are building an AI-native health insurer's outpatient claims pipeline in Dubai (all test data is fictional). Five agents each need a model. They run as Pi Durable agents on Cloudflare Workers and call JSON-schema tools in multi-step loops.
1. Enrollment: read an application and a free-text health declaration, list declared chronic conditions as ICD-10-CM category prefixes, then record an eligibility decision via a tool. About 3-4 model calls per run.
2. Claims intake/extraction: read an eClaimLink-style claim (structured) plus a free-text itemized bill, match bill lines to claim activities, total them and list mismatches, then record via a tool. About 3 model calls per run.
3. Medical coding review: check ICD-10-CM and CPT codes with lookup tools, detect diagnosis/procedure mismatch, unbundling and E/M upcoding, record findings. About 4 model calls per run.
4. Coverage and adjudication: apply plan rules from tools, decide pay or deny per claim line with denial codes; amounts are computed by a tool. About 4 model calls per run.
5. Fraud, waste and abuse review: compare a claim with member history and provider statistics, score signals 0-1 and recommend pay, review or hold. About 4 model calls per run.
Environment: every claim runs agents 2 to 5 in order (one run each, about 15 model calls per claim); about 300 claims and a few enrollments a day. A person approves every claim before payment, so a wrong pay decision costs reviewer time or money if missed, and an unnecessary review or hold costs reviewer time.
Existing evals: a Langfuse dataset of 14 labelled outpatient claims with experiments per model, scored per agent run (line decisions, fraud recommendation, bill mismatch, coding finding), per claim end to end (claim correct, payment correct, review load) and per model call (model calls, rejected tool calls, result recorded). Enrollment has two labelled fixtures and no dataset.
Constraints: UAE health-data residency. Under UAE Federal Law No. 2 of 2019 Art. 13, health data must be stored and processed inside the UAE, so each model endpoint must process data in the UAE; say where each endpoint processes data, and treat unknown as outside the UAE. Because all data here is fictional, we accept non-UAE endpoints only as a recorded residency gap. We already use Cloudflare Workers AI and OpenRouter. Quality and reliable tool calling matter more than cost: rank for the best quality.
